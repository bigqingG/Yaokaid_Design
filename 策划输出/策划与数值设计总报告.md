## 二、数值框架 v2.0 核心内容

### 2.1 法力价值模型（MVM）

**基础公理：1 法力 = 2 点属性价值（AV）**

标准身材公式：`AV = 2 × 费用 + 1`



| 费用 | 标准身材      | AV | MV  | 效率系数  | 调整后 MV |
| -- | --------- | -- | --- | ----- | ------ |
| 1  | 2/1 或 1/2 | 3  | 1.5 | ×1.0  | 1.5    |
| 2  | 2/3 或 3/2 | 5  | 2.5 | ×1.0  | 2.5    |
| 3  | 3/4 或 4/3 | 7  | 3.5 | ×1.05 | 3.68   |
| 4  | 4/5 或 5/4 | 9  | 4.5 | ×1.05 | 4.73   |
| 5  | 5/6 或 6/5 | 11 | 5.5 | ×1.1  | 6.05   |
| 6  | 6/7 或 7/6 | 13 | 6.5 | ×1.1  | 7.15   |
| 7  | 7/8 或 8/7 | 15 | 7.5 | ×1.15 | 8.63   |

### 2.2 效果价值量化（核心表）



| 效果类别          | 基础价值 (MV) | 触发折扣 |
| ------------- | --------- | ---- |
| 造成 1 点伤害（指向）  | 1.0       | ×1.0 |
| 造成 1 点伤害（随机）  | 1.0       | ×0.7 |
| 恢复 1 点生命（单位）  | 0.5       | ×1.0 |
| 抽 1 张牌        | 2.0       | ×1.0 |
| 获得 1 法力（临时）   | 1.0       | ×0.8 |
| 召唤 1/1 妖怪     | 1.0       | ×1.0 |
| 疾袭            | 1.0       | ×1.0 |
| 掩护            | 0.5       | ×1.0 |
| 护甲 1          | 0.5       | ×1.0 |
| 腐化（施加）        | 1.5       | ×1.0 |
| 派遣时触发         | —         | ×0.8 |
| 亡语触发          | —         | ×0.7 |
| 在场每回合         | —         | ×1.5 |
| 条件触发（天气 / 元素） | —         | ×0.5 |

### 2.3 卡牌总价值公式



```
妖怪牌：总MV = (攻+血)/2 + Σ(效果基础值 × 触发折扣)

法术牌：合理费用 = 总MV × 0.8（法术无身材，效率略高）

御术牌：总MV = 触发效果价值 × 0.6（暗置反制需对手配合）

超模判定：总MV > 费用 + 1.0

亏模判定：总MV < 费用 - 1.0
```

### 2.4 平衡性红线



| 限制项         | 红线值  |
| ----------- | ---- |
| 1 费妖怪最高攻击力  | 2    |
| 2 费妖怪最高攻击力  | 3    |
| 1 费法术最高伤害   | 2    |
| 单卡总价值 / 费用比 | ≤1.5 |
| 抽牌效率（每费抽牌数） | ≤0.5 |
| 7 费前稳定 OTK  | 禁止   |

### 4.4 系统性问题



1. **派遣效果折扣 0.8 偏高**：多个派遣效果卡超模，建议调整为 0.7

2. **群体效果价值低估**：全体 + 1/+1 类效果应按 N 个目标计算，N≥3 时价值显著

3. **持续在场效果折扣 1.5 偏低**：每回合触发的效果应按期望存活回合数（约 2 回合）计算

4. **天气条件增强的 0.5 折扣合理**，但复合天气卡（同时有基础效果 + 天气增强）需分别计算

## 六、数值设计工作流规范

### 6.1 新卡设计 Checklist

每张新卡设计完成后，必须填写：



* [ ] 牌组角色（启动 / 引擎 / 收益 / 干扰 / 终结 / 怪构筑）

* [ ] 费用档位与标准身材对比

* [ ] 所有效果逐项折算 MV

* [ ] 总 MV 与费用偏差（±1.0 以内为合理）

* [ ] 风险等级（低 / 中 / 高）

* [ ] 反制点（对手如何处理）

* [ ] 可能被滥用的组合

### 6.2 数值调整原则



1. **优先调数值，不轻易改机制**：攻 / 血 / 费微调优先

2. **一次只改一个变量**：避免多重调整无法归因

3. **记录调整历史**：原值→新值→原因→预期效果

4. **观察期≥1 周**：调整后至少观察一个版本周期
