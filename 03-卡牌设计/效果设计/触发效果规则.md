# 触发效果规则

## OneShotEffect

解析目标 → 条件检查 → 执行 success/failure Actions → flush 事件。

适用：派遣效果、法术效果、天气预测、一次性治疗/伤害/抽牌。

## AuraEffect

事件触发 → 标记 DirtyManager → 批量刷新 → 重算 Modifier。

适用：妖怪或设备的在场光环、天气全局效果、阵列范围效果。

## 御术触发

激活御术 → 支付费用 → 暗置监听 → 敌方回合匹配事件（特殊回合另行指定）→ 按激活顺序触发一次 → 结算后失效。卡面省略“下一次”。

御术不作为持续收益引擎使用。如果一张牌写成“每回合一次，我方……”且没有暗置反制结构，应改由妖怪或设备承载。

## 表现提交协议

Request → Present → Commit → Resolve → Aftermath

## 时机与事件范围

- “将受到Y点伤害时”在伤害实际提交前执行减免或替换；“受到伤害后”在伤害已结算后触发收益。
- 触发型在场效果默认只在我方回合监听；敌方回合或双方回合生效须在卡面明确标注。派遣、亡语、御术各按自身时机执行。
- 选手常驻触发同样遵守此默认值。次数写“每回合一次”；未写次数的持续监听按每个合格事件触发，不隐含首次限制。
- “友方妖怪攻击后”不限定攻击目标类别，包含攻击合法敌方妖怪、选手及设备；限定目标类别时须明写。反击不是攻击事件。“若存活”在攻击及死亡处理后检查事件中的攻击妖怪。完整模板见《卡牌文本规范》。
- “额外获得法力槽时”只匹配卡牌效果的额外增槽事件，排除回合开始正常增长；事件携带获得槽数，一次多槽默认仍触发一次。
- 一次性法术可记录指定时点的单次延迟结算，保留原目标引用，结算后移除记录。例如“回合结束时，对其造成2点伤害”。这不是赋予目标一项持久能力。

## 下一次伤害修正

- “下一次伤害+X/-X”只应用于伤害队列中首个符合条件的单目标条目。卡面不必补写“单体伤害”。
- 群体伤害拆成逐目标条目，使用既有伤害队列顺序，不新增选目标或排序操作。第一个符合条件的目标消耗这次修正，其余目标按原伤害结算。
- 例：对三个目标各造成2点元素伤害，持有“下一次元素伤害+2”，结果依次为4、2、2；持有“下一次元素伤害-1”，结果为1、2、2。
- 先匹配阵营、元素及期限，再应用修正并消耗一次。明确限定元素伤害的修正不会被普通伤害提前消耗。减伤最低为0，不变成治疗。
- 已失效、无合法目标而被跳过的条目不消耗；合法条目应用修正后即消耗，即使其之后被其他效果完全防住。

## 费用修正的时机

- “获得费用±X”在支付费用前应用。限定下一张、第N张牌的效果只用于那次使用，不在牌打出后追溯退费，也不成为回手后反复使用的永久折扣。
- 条件费用效果在条件满足时提供一份修正；重复刷新费用不会重复叠加同一来源。同名多来源如何叠加遵循通用增益规则，费用最低为0。
- 本回合限时奖励未使用则到期；未写回合期限的下一张牌奖励保留到使用。已结算产生的奖励不会因来源设备被拆除而撤销；持续依赖设备在场的费用效果随来源失效。

## 单次条件奖励

“若其造成元素伤害，抽1张牌，然后弃1张牌”是所指法术的一次条件奖励，群体或多段命中不增加奖励次数；只有明确写“每次”“每当”才逐事件重复。

## 操作入口与事件边界（2026-09-06）

- 在场效果没有手动发动入口；必须由派遣、亡语、回合时点或具体事件驱动。每回合一次仅是次数限制。
- 一个指向性法术或派遣最多消费一次目标指定；后续随机、相邻对象自动派生，不发起额外指向请求。详见[卡牌使用与目标选择](../../02-玩法设计/卡牌使用与目标选择.md)。
- “额外抽牌”匹配效果抽牌，排除正常规则抽牌；“加入手牌”不自行发出抽牌事件。
- “每回合一次”的抽牌或弃牌奖励在本回合第一次符合条件时消耗次数，不因同次处理多张牌重复奖励；按张数计算的能力必须明确写出。
- “若以此触发元素反应”绑定前文伤害与其反应结果，单次奖励不得再次回到同一条件。
- 下回合失去法力登记为一次延迟扣减，在该回合法力补满之后执行；额外增槽在补满之前执行。
- 沃土精华由归根入土生成后独立存在，按它自己结算时的天气选择增益，生成时的天气不锁定结果。
